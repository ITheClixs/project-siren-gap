# Advisor Committee Review — Gate G1

Date: 2026-07-17. Scope reviewed: close-read memos, core library, T1–T9, profiling.

## Theorist

1. **Your T1 tests generators and random words, not the group.** Passing T1 shows the implemented
   (d, j, perm) action is *a* symmetry action; it cannot show D∞≀Sₙ is the *whole* group — that is
   PO-2, and until PO-2 lands every "exact canonicalization" claim must say "exact w.r.t. the
   implemented group." Add that qualifier to c_sort/c_align docstrings before any study uses them.
   [Response: accepted — wording task queued for G2 alongside PO-2; CLAIMS.md row 1 already scoped
   as containment-only.]
2. **c_sort's orbit-collapse test uses generic Gaussian weights.** Real fitted weights concentrate
   near strata (small ‖u‖ for pruned-ish neurons, near-tie norms). T3 green on Gaussians says
   nothing about behavior on the actual data distribution — the margin diagnostics exist, but no
   test pins behavior *at* ties. Write the tie-stress test (duplicate neurons, w = 0, u = 0) at G2
   and decide the documented tie-breaking policy. [Response: accepted — added to G2 checklist; PO-3
   audit will report empirical distance-to-strata on the first real corpus.]
3. **Sinkhorn is currently decorative.** It reduces to "Hungarian on the plan, fallback greedy" and
   T7 only checks it is not-worse-than-greedy. Either give it a real role (differentiable/learned
   canonicalization path, Ch3.4) with a test that exercises annealing, or drop it until needed.
   [Response: partially accepted — it stays (Ch3.4 dependency) but the G2 notebook must log it as
   unvalidated-beyond-T7.]

## Empiricist

1. **T9's determinism cell is narrow:** B=2, 150 steps, width 16, one dtype, one torch version.
   MPS gap 0.0 here does not license "MPS is deterministic" — it licenses "this workload was".
   Before G3 dataset generation, rerun T9 at production width/steps/batch and archive the report
   per config. [Response: accepted — G3 entry criterion added.]
2. **T4's PSNR threshold (20 dB on smooth synthetic) is weak** and unconnected to the Ch4 quality
   gate (task-referenced render classification). Fine for a property test; do not let anyone quote
   it as fit quality. The real gate arrives with INR-Bench. [Response: agreed — noted.]
3. **Profiling uses random-noise targets.** Real images fit faster/slower depending on spectrum;
   noise targets give a pessimistic-ish step count but the *throughput* (steps/sec) is
   image-independent at fixed architecture, which is what the ledger needs. State this in the
   ledger footnote. [Response: accepted — footnote added.]

## Systems reviewer

1. **The venv is not pinned.** pyproject floors (torch>=2.5) resolved to torch 2.13.0 today;
   tomorrow's fresh install may differ and T9's determinism claim is version-scoped. Freeze a
   lockfile (`uv pip freeze > requirements-lock.txt`) now and record torch build in every sidecar.
   [Response: accepted — lockfile committed at G1 close.]
2. **CI has no cache and no MPS runner** — fine (GitHub has no Apple-silicon MPS runners on free
   tier); but then CI green ≠ G-gate green. The gate criterion "T1–T9 green on MPS+CPU" is
   satisfied only by the local run; record the local pytest output hash in the notebook at every
   gate. [Response: accepted — notebook logs the local run.]
3. **results/t9_mps_report.json is committed but regenerated by tests** — nondeterministic churn in
   diffs if torch version changes. Acceptable (it is the point), but name it with the torch version
   at G3 when multiple configs exist. [Response: accepted.]

## Verdict

G1 passes once the compute ledger carries measured throughput and the lockfile is committed. The
close-read set is the strongest part of this gate; the Shamsian SIREN-bias failure finding
materially improves the program's motivation and must appear in Paper A/B intros.
